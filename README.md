## 1. Основные достижения

В ходе третьего этапа разработки была продолжена работа над внутренней архитектурой NEXUS AI. Основное внимание уделено системе логирования, обработке результатов выполнения функций и проверке наличия Ollama в системе.

### 1.1. Система логирования (Logging System)

Разработана и подключена базовая система логирования, которая позволяет записывать события работы программы в отдельный файл `core/logs.txt`.

Реализована запись следующих данных:

- Дата и время события.
- Уровень важности сообщения.
- Название модуля, из которого поступило сообщение.
- Само сообщение.

Для получения текущего времени используется стандартная библиотека `time.h`.

Изучены и применены следующие инструменты:

| Функция / тип | Назначение                               |
| ------------- | ---------------------------------------- |
| `time_t`      | Хранение календарного времени            |
| `time()`      | Получение текущего времени               |
| `localtime()` | Преобразование времени в локальную дату  |
| `struct tm`   | Представление компонентов даты и времени |
| `strftime()`  | Формирование строки даты и времени       |

Формат временной метки:

`YYYY-MM-DD HH:MM:SS`

### 1.2. Уровни логирования (Log Levels)

Добавлено перечисление `LogLevel` с тремя уровнями:

- `LOG_INFO` — информационные сообщения об успешных операциях и обычных событиях.
- `LOG_WARNING` — предупреждения о потенциальных проблемах.
- `LOG_ERROR` — сообщения о возникших ошибках.

Для преобразования значений перечисления в текстовые обозначения используется `switch`.

Это позволяет не передавать произвольные текстовые уровни при каждом вызове функции, а использовать заранее определённые значения.

### 1.3. Структура записи журнала

Функция `nexus_log_write()` была расширена. Теперь она принимает три параметра:

- `LogLevel level` — уровень сообщения.
- `const char *module` — название модуля.
- `const char *message` — текст сообщения.

Пример вызова:

`nexus_log_write(LOG_INFO, "AI", "Ollama found in PATH\n");`

Пример результата в `logs.txt`:

```text
[2026-11-08 01:03:51] [INFO] [STARTUP] Starting Nexus AI
[2026-11-08 01:03:51] [INFO] [STARTUP] Loading core modules
[2026-11-08 01:03:56] [INFO] [AI] Ollama found in PATH
```

Таким образом, журнал позволяет отслеживать события сразу из нескольких модулей.

## 2. Развитие AI-модуля

Следующим этапом стала работа с модулем `modules/ai`.

### 2.1. Проверка наличия Ollama

Реализована функция:

`nexus_check_ai(void)`

Для проверки используется команда Windows:

`system("where.exe ollama");`

Она позволяет проверить, доступна ли команда `ollama` через системный `PATH`.

Результат выполнения сохраняется в переменную `status`.

- `status == 0` — команда завершилась успешно, Ollama найдена.
- `status != 0` — команда завершилась с ошибкой.

### 2.2. Разделение статусов

В процессе разработки закреплён принцип разделения ответственности между функциями.

**AI-модуль:**

- `AI_SUCCESS` — Ollama обнаружена.
- `AI_ERROR` — Ollama не обнаружена.

**Система логирования:**

- `ERROR_SUCCESS` — запись выполнена успешно.
- `ERROR_LOG` — при записи возникла ошибка.

Это позволяет не смешивать ошибки разных подсистем. Например, отсутствие Ollama является ошибкой проверки AI-модуля, а не ошибкой записи журнала.

### 2.3. Логирование результатов проверки

Добавлена запись как успешного, так и неуспешного результата проверки Ollama.

- При обнаружении Ollama записывается `LOG_INFO`.
- Если Ollama не найдена, записывается `LOG_ERROR`.

## 5. Проблемы и решения

Во время разработки возникло несколько технических проблем.

**Проблема №1 — неправильный путь к заголовочному файлу.**

При подключении `logs.h` из AI-модуля компилятор не мог найти файл.

**Решение:** разобраны относительные пути и исправлено подключение через `../../core/logs.h`.

**Проблема №2 — неправильное описание успешного события.**

При успешном обнаружении Ollama в журнал первоначально передавалось сообщение о том, что она не установлена.

**Решение:** исправлен текст сообщения на `Ollama found in PATH`.

**Проблема №3 — смешивание кодов ошибок.**

Возник вопрос, какой статус должна возвращать функция проверки AI, если обнаружение Ollama не удалось.

**Решение:** закреплено разделение ответственности. AI-модуль возвращает собственный результат проверки, а функция логирования — результат записи в файл.
